# game-server 部署协议（部署前必读）

> **效力**：即日起对**所有**游戏服务器（odoo `/opt/game-server`）的部署操作生效——无论人工还是 AI 会话，无论走 SSH 还是面板。违反本协议造成的线上事故由操作者负责。
>
> **背景**：2026-10-07 消消乐 SSO 构建与旧版全量构建（含 risk/eco/麻将模块、无 sso-exchange 路由）**三次互相覆盖** `/opt/game-server/dist`，导致 game.yourbao.cn / game.joho.cn 全部游戏 SSO 登录 404 不可用。本协议即为根除该事故而立。

## 一、铁律（任何情况下不得违反）

1. **禁止服务器构建**：`npm ci` 仅限依赖变更时在服务器执行安装（非构建）；`nest build`/`tsc` 一律在本地完成后上传产物。服务器内存不足以支撑构建。
2. **禁止覆盖式部署**：不得把任何包解压/拷贝到 `/opt/game-server/dist`（该目录已被 release+symlink 机制取代，见第三节）。
3. **`.env*` 永不进包**：部署 tar 包只允许含 `dist/`、`seeds/`、依赖指纹文件。改环境变量 = 直接编辑服务器上的 `/opt/game-server/.env` / `.env.prod`，然后 restart。
4. **部署后必须自检**（过渡期与本协议目标态均适用）：

```bash
# 自检 1：产物含关键路由（缺任一 = 旧包/坏包，禁止 restart，立即回退）
grep -rq sso-exchange <产物>/dist/src || echo "BAD: 缺 sso-exchange"
grep -rq health     <产物>/dist/src || echo "BAD: 缺 health"

# 自检 2：重启后线上探针（400=路由在（参数校验），404 Cannot POST=旧包，立即回退）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/health                                  # 期待 200
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:3000/api/client/v1/auth/sso-exchange  # 期待 400
```

5. **唯一部署入口**：统一走 `scripts/deploy.mjs`（构建→自检→上传→原子切换→健康检查→失败自动回滚）。脚本落地前为**过渡期**，手工部署必须遵守第四节流程并在会话记录中留下部署说明。

## 二、应用码（app_code）规则

- 所有游戏共用本 Nest 服务，场景由应用码区分（如消消乐 `game-xxl`）。**新游戏上线前必须先在 SSO 侧注册新 app_code**（zhao-sso `sso_apps`，当前 9 个：game-xxl=消消乐 id=8、通用 game id=9 等），并确认模块路由按应用码隔离。
- 部署的是**同一个构建**——不存在"为某个游戏部署另一个包"。发现"另一个游戏的包"，说明来源是旧分支/旧仓库，禁止部署。

## 三、目标态布局（已于 2026-10-07 生效）

> 迁移已完成：current 已指向 releases/20261007-232921，systemd ExecStart=node current/dist/src/main。dist 目录已改名 dist_pre_atomic_20261007-232201，禁止再写入。

```
/opt/game-server/
├── releases/<yyyyMMdd-HHmmss>/   # 每次部署独立目录（dist/ seeds/ 依赖指纹）
├── current -> releases/<最新>    # symlink，唯一切换点
├── .env / .env.prod              # 固定于此，永不随包
└── node_modules/                 # 共享生产依赖（依赖指纹变更才 npm ci）
```
- systemd：`WorkingDirectory=/opt/game-server` + `ExecStart=/usr/local/bin/node current/dist/src/main`
- 切换 = 改 symlink（原子）；回滚 = symlink 指回上一 release + restart
- `releases/` 保留最近 5 版，部署成功后自动清理更旧版本

## 四、过渡期手工部署流程（deploy.mjs 落地前）

1. 本地 `nest build`；对本地 `dist/` 执行自检 1（含 sso-exchange 才是有效包）
2. `tar -czf gs-dist.tgz dist seeds`（**确认 tar 列表里没有 .env\*、node_modules**）
3. `scp` 到服务器 `/tmp/`
4. 服务器：`cp -a /opt/game-server/dist /opt/game-server/dist_prev_<用途>_<时间戳>`（先备份）
5. 解压替换 `dist` + `seeds` → 执行自检 1 → `systemctl restart game-server`
6. 等 5 秒 → 执行自检 2（线上探针）；任一失败：立即用第 4 步备份回退 + restart + 重新自检
7. 在本文件底部「部署记录」追加一行

## 五、回滚

- 目标态：`ln -sfn /opt/game-server/releases/<上一版> /opt/game-server/current && systemctl restart game-server`
- 过渡态：用 `dist_prev_*` 最新备份回补 + restart
- 回滚后必须跑自检 2 确认恢复
