# 方块（tetris）迁移与初始化说明

> 给部署人执行数据库侧变更用。配套见 `DEPLOY.md`（部署流程）与 `联调自测清单.md`（接口验证）。

## 1. 迁移文件

`d:/zhao/game-server/src/migrations/0007_tetris.ts`（迁移类名 `TetrisTables1759700000007`）。

创建 4 张 `tetris_*` 表 + 幂等唯一索引，与消消乐 `xiao_*` 完全隔离、互不相通。

## 2. 执行命令

```bash
cd d:/zhao/game-server
npm install          # 依赖无新增可跳过；有新增则必装
npm run build        # 先构建（迁移在 src/ 下以 ts-node 运行，但保险起见先 build）
npm run typeorm:run  # 执行全部未应用的迁移，含 0007_tetris
```

> `typeorm:run` 按 `src/data-source.ts` 顺序执行尚未落库的迁移；`0007` 是新增项，执行即创建本游戏的 4 张表。
> 若服务器是 Windows（PowerShell），把 `cd` 换成 `cd d:/zhao/game-server`，命令本身在 npm script 内一致。

## 3. 建表清单（前缀 `tetris_`）

| 表 | 关键字段 | 索引 |
|---|---|---|
| `tetris_player_points` | `player_id` bigint **UNIQUE**, `balance`, `total_earned`, `total_spent`, `updated_at` | 主键 id |
| `tetris_point_logs` | `player_id`, `amount`, `type`, `ref_id`, `balance_after`, `created_at` | `idx_tetris_point_logs_player(player_id,created_at)`、`idx_tetris_point_logs_type(type)`、**UNIQUE** `idx_tetris_point_logs_player_ref(player_id,ref_id) WHERE ref_id IS NOT NULL`（幂等键） |
| `tetris_player_profile` | `player_id` bigint **UNIQUE**, `best_score`, `plays`, `signin_streak`, `last_signin_date`, `items` jsonb, `updated_at` | 主键 id |
| `tetris_player_skins` | `player_id`, `skin_id`, `source`, `created_at` | **UNIQUE**(`player_id`,`skin_id`)、`idx_tetris_player_skins_player(player_id)` |

## 4. 回滚

```bash
cd d:/zhao/game-server
npx typeorm-ts-node-commonjs migration:revert -d src/data-source.ts
```

执行 `down()`：按依赖顺序 `DROP TABLE` 上述 4 张表。

> 注意：`migration:revert` 每次只回退**最近一次**已应用迁移。若需多步回退，重复执行。回退前请确认无线上数据需保留（tetris 为全新游戏，回退即清空其全部云端数据，可接受）。

## 5. 初始化数据（结论：**无需 seed**）

- **皮肤目录**由前端 `SkinManager` + 后端 `skins.service.ts` 的 `BUILTIN_SKINS` 共同定义（classic/warm 免费、retro/nostalgia 各 30 积分）。后端**不**单独 seed 皮肤表；玩家解锁记录按需写入 `tetris_player_skins`。
- **玩家积分 / 进度行懒创建**：首次 `GET /points` 或 `GET /progress` 时自动建 `balance=0` / 空进度行，无需预置数据。
- 若运营后续希望给全体玩家默认赠送某皮肤，再单独编写 seed 脚本（当前不在交付范围）。

## 6. 验证迁移成功

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_name LIKE 'tetris_%';
```

应返回 4 行：`tetris_player_points` / `tetris_point_logs` / `tetris_player_profile` / `tetris_player_skins`。

索引核对（可选）：

```sql
SELECT indexname FROM pg_indexes WHERE tablename LIKE 'tetris_%';
```

应能看到 `idx_tetris_point_logs_player_ref`（含 WHERE 条件）等。
