## 二、在哪里转发（两种方式）

### 方式 A：游戏内分享（推荐，走微信卡片）
1. **微信内**打开游戏入口链接（或从聊天记录点开历史分享卡）。
2. 未登录会自动跳 SSO，微信内自动登录后返回游戏。
3. 进入游戏后点**分享/邀请按钮** → 微信弹出转发卡片。
4. 卡片标题/描述由 A/B 实验自动下发（温情版或挑战版文案），缩略图为对应分享图（粉花 / 靛蓝闪电），**每个用户随机命中一个版本**。
5. 转发给**好友或微信群**即完成一次分享。

> 分享链接自带归因参数：`?camp=xxl-share-2026&v=<变体id>&st=<标签>`，无需手工拼接。

### 方式 B：直接转发链接（轻量测试）
把入口链接直接发到群里即可。打开者若带 `camp/v/st` 参数会被完整归因（打开事件计入对应变体）。

### 打开者侧发生什么
- 好友点开卡片/链接 → 未登录则跳 SSO 登录（**登录回来归因参数不丢**）→ 系统记录一次「打开」并归因到分享者的文案变体。

## 三、测试广告效果（数据在哪看）

### 口径说明
| 指标 | 来源 | 含义 |
| --- | --- | --- |
| 曝光 impressions | browser-log（page-view 带 abVariant） | 分享卡展示次数 |
| 点击 clicks | click-event（打开事件） | 好友打开分享的次数 |
| CTR | 点击 / 曝光 | **判优核心指标** |
| 订单/佣金 | order | 消消乐无下单，恒为 0 |

### 查看报表
接口（需登录后台的账号，admin 或 channel-admin 角色均有权限）：

```
GET https://h.joho.cn/api/zhao-studio/v1/admin/channel-report
    ?channelCode=xxl-wechat
    &startDate=2026-10-07T00:00:00.000Z&endDate=2026-10-08T00:00:00.000Z
    &groupBy=variant
Authorization: Bearer <后台登录JWT>
```

返回示例（测试期数据）：
```json
{ "byVariant": [
  { "variantName": "温情版", "impressions": 3, "clicks": 2, "ctr": 66.67 },
  { "variantName": "挑战版", "impressions": 0, "clicks": 0, "ctr": 0 }
]}
```

> TAdmin 后台接入：带登录 JWT 调用上述接口即可渲染变体对比表。

### 测试操作建议（造数据）
1. 微信里 2~3 个号分别打开游戏 → 分享到同一测试群。
2. 换不同好友点开分享卡（每台设备算一次打开）。
3. 半小时后在报表里看两个变体的曝光/点击是否分别累计。

## 四、判优与回滚

- **观察期 3~7 天**：曝光量足够后（建议每变体 ≥100 曝光），比较两变体 CTR。
- **挑优**：把 winning 变体 weight 调高（或停掉 experiment 的另一变体）——后台编辑 ab-variant 的 weight 字段即可。
- **回滚**：游戏端把环境变量 `MARKETING_CAMPAIGN_CODE` 置空并重发 bundle → 恢复旧分享逻辑（默认文案）；Strapi 侧改动纯增量，无需回滚。

## 五、常见问题

| 现象 | 说明 |
| --- | --- |
| 打开链接跳到登录页 | 未登录正常现象；微信内自动登录后返回，归因不丢 |
| 分享卡还是旧文案 | 微信缓存卡片文案，链接参数变化即可刷新；分享图走 CDN 带版本号 |
| 报表曝光比点击少 | 曝光口径含渠道码过滤；10-07 前的测试数据已修正，正常流量不受影响 |
| 数据延迟 | 报表有 5 分钟内存缓存；改日期参数可绕过 |
| 游戏内积分/资源 401 | 游戏服务端链路，与营销统计无关 |
