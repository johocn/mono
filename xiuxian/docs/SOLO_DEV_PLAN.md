# 《修仙·凡人之路》单人独立开发完整规划方案

> 文档状态：v1（2026-10-31 创建）
> 维护方式：本方案随阶段推进在 `docs/` 更新，阶段完成在文末「阶段状态表」勾选。
> 适用对象：单人独立开发者（本项目当前为一人 + AI 工具链）。

---

## 1. 执行摘要

本项目（LayaAir 3.3.4 + TypeScript + Vite 的 2D 仙侠 RPG）**系统骨架已达标甚至领先**——双章节垂直切片、36 个数据驱动养成/战斗/任务/经济/元系统全部可玩通。真正的差距在**表现层工业化**（全程序化美术、零音频资产）与**工程化**（无 CI、上帝类）。

本方案回答三个问题：单人单打独斗能到多高？怎么一步步到？过程中如何不被范围和精力拖垮？

**核心结论**：单人可达的最高现实高度是 **「AI 辅助国风 indie 品质 + 深度系统养成 + 完整可玩内容量」**，靠已领先的「数据驱动系统深度」与「国风美术氛围」取胜，而非硬拼商业大作 3A 美术精度。

---

## 2. 目标定位（不可动摇基线）

| 维度 | 定位 |
|---|---|
| **可达最高高度** | AI 辅助国风 indie 品质 + 深度系统养成 + 完整内容量，能上线 itch.io / Steam 并有留存 |
| **不硬拼的目标** | 《凡人修仙传/诛仙》手游级 3A 美术精度（需专业原画/动画/音频团队 + 预算，单人 + AI 不可持续；本项目韩立形象反复逐件打磨即为证据） |
| **差异化取胜点** | 已领先的「数据驱动系统广度与深度」+ 国风美术（AI 生图 + Spine 轻动画）+ 内容量 |
| **核心铁律** | 范围蔓延是单人最大杀手，非核心果断砍；AI 可补齐程序/美术/音效/QA/发行角色，但「fun（乐趣/手感）」必须由本人把控 |

---

## 3. 现状基线（2026-10-31 已确认）

**技术栈**：LayaAir 3.3.4（本地 vendored 运行时 `public/libs/`）、TS 5.4.5 + Vite 5.2.0（strict）、后端零依赖 `node:http + node:sqlite`（Node 22）。

**系统成熟度（领先）**：
- `src/data/` 共 36 个数据驱动表（skills 24 技能 / monsters 7 怪 2 Boss / talents / artifacts / gems / realms / schools / zones / tower / arena / beasts / events / dungeon …）。
- `data/story/chapter1`(18.9KB) + `chapter2`(7.26KB) 双章节：对话树 + 任务链 + NPC 点位。
- P0 七项（灵根/宝石/功法/秘境/挂机/战令/签到）已闭环；P1（天劫/炼丹/灵兽/镇妖塔/竞技场/飞升/活动/社交）已落地。
- 测试资产：`test/smoke.cjs`(~1177 断言) + `smoke.server.cjs` + `browser-check.cjs`(Playwright E2E) + `stubs.cjs`(Node 跑真实源码)。

**短板清单**：
1. 全程序化美术（`src/core/Rig.ts` 色块骨架 + AI 整图立绘；场景等距色块 `IsoMap.ts`）。
2. **音频零资产**（`Sfx.ts` 纯 WebAudio 振荡器合成，无 mp3/wav/ogg）。
3. `Game.ts`(149KB) / `Player.ts`(75KB) 上帝类，模块边界模糊。
4. 无 CI、无视觉回归。
5. 素材管线作坊式（`scripts/fix-hanli-edge.py` 须逐张手跑 + 逐帧调参 + 截图肉眼验证）。

---

## 4. 单人开发铁律与效率取舍

- **精力稀缺**：每周固定产出节奏，单阶段 ≤ 6 周；优先「可玩可演示」而非「完美」。
- **美术取舍**：AI 生图 + Spine 轻动画即可，不追手绘逐帧；场景用程序化 / 开源瓦片。
- **音频取舍**：先补核心音效（打击/施法/UI/受击）+ 1–2 首国风 BGM，配音放后期。
- **架构取舍**：先接 CI + 通用素材管线（立即降摩擦），上帝类拆分为渐进式（不阻塞内容开发）。
- **行业铁律**：垂直切片先于全功能；周度里程碑必须可度量；「Solo dev fails from lack of structure, not talent」。

## 6. 分阶段执行计划

> 节奏：兼职单人，周度产出；单阶段 4–6 周上限，超出则砍范围。

### 阶段0 — 定位与方案文档化（1 周）
- **里程碑**：目标定位共识、方案落盘。
- **交付**：`docs/SOLO_DEV_PLAN.md`（本文件）、`README.md` 补定位声明。
- **依赖**：无。
- **风险**：定位摇摆 → 应对：以「AI 辅助国风 indie + 深度系统」为不可动摇基线。
- **完成标志**：本文档与 README 定位段落地，团队（本人）确认。

### 阶段1 — 工程治理（低风险高收益，4–6 周）
- **里程碑**：CI 绿、视觉回归基线建立、素材可批量量产、上帝类初步解耦。
- **交付**：
  - GitHub Actions 跑 `npm test` + `browser-check.cjs`；
  - 截图 diff 基线（捕获「立绘边缘/比例/配色」类回归）；
  - `fix-hanli-edge.py` **通用化**为「任意角色抠图管线」（入参角色名 → 品红键控 + 连通域清理 + 去染 + 预缩锐化，批量产 `cut/*.png`），消除逐张手跑；
  - 按 indie-blueprint / 史莱姆分层 + LayaAir 架构审查清单拆分 `Game.ts`/`Player.ts`（先抽 `EventBus` + `Manager` 层，渐进式）。
- **关键依赖**：现有 `smoke.cjs`/`stubs.cjs`/`fix-hanli-edge.py`。
- **风险**：拆分类阻塞内容开发 → 应对：渐进式抽模块，不一次性重写。
- **完成标志**：push 后 CI 自动绿；新增角色素材一条命令产出；`Game`/`Player` 核心逻辑拆出 `EventBus` + 至少 2 个 Manager。

### 阶段2 — 表现层工业化（6–8 周）
- **里程碑**：有声、立绘动、场景像样、打击有手感。
- **交付**：
  - 音频资产库（打击/施法/UI/受击）+ 1–2 首国风 BGM，替换 `Sfx.ts` 合成音；
  - 主角 + 关键 NPC 接入 **Spine/Live2D 骨骼动画**替程序化骨架（`Rig.ts` 接入真实动画资源）；
  - 等距瓦片美术 + 环境光/天气；
  - 战斗手感 **per-skill 配置**（顿帧/震屏/特效/音效打通 `Fx.ts` 与 `data/skills.ts`）。
- **关键依赖**：阶段1 素材管线、OpenGameArt/Freesound 资产、Spine 运行时集成。
- **风险**：AI 美术一致性差 → 应对：资产规范文档 + 管线固化；音频版权 → 应对：只用 MIT/Apache/CC0。
- **完成标志**：战斗有音效 + 打击顿帧震屏刀光；主角立绘为骨骼动画；场景有瓦片与光照。

### 阶段3 — 内容扩展与工具化（4–6 周）
- **里程碑**：章节/系统可低成本扩量、填表即生效。
- **交付**：基于 `data/` 扩章节 3+ / 怪物 / 技能 / 活动；可视化内容编辑器（技能/怪物/地图填表，参考 `cultivation-simulator` 机制层）；复用 `data/story` 结构。
- **关键依赖**：阶段1 数据驱动根基、阶段2 编辑器。
- **风险**：scope creep → 应对：MVP 优先、非核心果断砍。
- **完成标志**：新增一章内容仅通过填表 + 少量逻辑完成，无需改动核心。

### 阶段4 — 剧情演出升级（3–4 周）
- **里程碑**：过场有立绘演出、叙事有 AI 弹性。
- **交付**：Live2D 表情/过场动画替黑边文字；参考 `XianTu` 引入 **AI 动态叙事**（可选接大模型，需后端 `server/server.cjs` 扩接口）。
- **关键依赖**：阶段2 立绘动画、后端 AI 接口。
- **风险**：AI 叙事成本/稳定性 → 应对：离线预设剧情树为主、AI 仅生成事件文本。
- **完成标志**：关键过场有立绘演出；剧情事件可由配置/AI 弹性生成。

### 阶段5 — 平台与发行（4–6 周）
- **里程碑**：移动端可玩、可发行、有留存运营。
- **交付**：微信小游戏/移动端深度适配（`Input.ts` 触控已具基础）；itch.io / Steam 发行包；社区 + 留存（复用已落地战令/签到/社交 `data/`）。
- **关键依赖**：阶段1–4 全部。
- **风险**：单人精力 burnout → 应对：周度可度量里程碑、范围管控。
- **完成标志**：移动端可完整体验；发行包可上传平台；留存系统在线运营。

## 7. 行业实践参考（已检索）

- **"Solo dev fails from lack of structure, not talent"**：结构 > 天赋，垂直切片 + 周度产出。
- **AI 工具链**（Claude/ChatGPT）用于头脑风暴、大功能拆解、抓 scope creep；AI 补齐多岗位但**无法生成「fun」**。
- **资产来源**：OpenGameArt 免费图、Aseprite 像素、Freesound 免费音效、引擎官方商店免费模板质量更高。
- **许可证红线**：GPL 不可闭源商用，优先 MIT/Apache/CC0。

## 8. 跟踪评估方法

- **阶段进度**：文末「阶段状态表」勾选 + 各阶段「完成标志」逐条核对。

- **内容扩量效率**：新增 1 章/1 系统所需的代码改动行数（应随编辑器与数据驱动下降）。
- **手感基线**：保留 `test/dbg-robe-anim.cjs` 逐 clip 幅度体检 + `shot-hanli.cjs` 实机截图，作为表现层回归基准。
