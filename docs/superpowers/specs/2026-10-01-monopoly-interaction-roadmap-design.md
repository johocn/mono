# 大富翁（monopoly）互动玩法升级 · 总纲与排期设计

- 日期：2026-10-01
- 范围：`d:\zhao\monopoly`（PixiJS 8 + TypeScript，等距棋盘，390×844 舞台）
- 状态：总纲已确认（采纳排期方案 A），本文档为 M18–M21 的上位约束，各里程碑另出详细设计

## 1. 缘起（客户反馈原文要点）

客户反映该游戏**缺少原版《大富翁》的沉浸感与「互坑」快感**，具体诉求：

1. 落子到格的沉浸感不足
2. 想用**路障**挡自己或拦截别人、**拆别人家**——这类对抗快感缺失
3. 希望**开局只显示棋盘**，买地后建筑一点点生长，直到**五星级**
4. **建筑物颜色与业主颜色一致**，一眼看出棋盘建筑归属谁
5. 玩得不好要**破产拍卖土地，价高者得**
6. **股票交易缺功能**：现在**没有**「指定买哪支 / 卖哪支 / 买多少」的入口（客户原话「股票不能指定买那只，也不能选择性卖出」是**抱怨缺失**）；另需新增**涨跌卡 / 红利卡**及其使用入口
7. **路障、炸弹没有释放对象**：结算层支持目标，但 UI 自动挑目标，玩家没有「选目标」这一步

总目标：对齐《大富翁》能力，确保互动玩法**超越**过去，学习先进棋牌游戏的设计，开发新玩法——不是简单加几个按钮。

### 2.1 不可破坏的既有约束

- **17 个商家格一个不动**（业主书面授权清单是产品价值所在，见 `docs/manual-mono.md` M16 节）。
- **确定性**：一律 `makeRng(seed)` 分流，禁止 `Math.random`（回放与 e2e 可复现）。
- **四级可回退体系**（L1 元素覆盖 → L2 皮肤包 → L3 默认皮肤 → L4 内建 `fb`），裸值只允许出现在 L4 内建兜底；`tools/check-hardcoded.mjs` 与 eslint-plugin-mono 为闸门。
- **公有领域合规**：西游 / 三国形象与原著原文可用，影视与网络二创台词一律不用，美术不照搬商业游戏 / 影视剧造型。
- 每次功能交付 = **实现 + 单测/闸门 + 手机视口截图（390×844 @dpr2）+ 手册条目**，收尾一次完成（提交 → 推送 → 部署）。

## 3. 子项目分解与依赖

依赖为**链式**：`M18 → M19 → M20 → M21`。

理由：拍卖他人的地、拆他人的楼，若棋盘上看不出「这是谁的地、几星」，玩家感知不到得失，互坑与竞拍都失去戏剧性。故视觉归属必须先立。

| 里程碑 | 子项目 | 覆盖诉求 | 依赖 | 风险 |
|---|---|---|---|---|
| **M18** | 棋盘生长与归属可视化 | ③ 空盘起步逐级生长、④ 楼体随业主配色 | 无（视觉底座） | 高：推翻「未售地块与 v5 样张逐像素一致」基线 |
| **M19** | 对抗玩法与落子沉浸 | ② 路障 / 炸弹 / 拆屋 + 选目标、① 落格特写 | M18 | 中：动 core 结算 + UI 新交互态 + AI 决策 |
| **M20** | 经济闭环：拍卖 / 自由出售 / 股票交易 / 股票卡片 | ⑤ 价高者得（所有权转移）、⑥ 买卖标的与数量可选、⑦ 涨跌卡 + 红利卡 | M18 | 中：拍卖为新子系统；股票与卡片需补 UI 入口（**非砍功能**） |
| **M21** | 全新玩法（超越原版） | 「学习先进棋牌玩法，开发全新玩法」 | M18–M20 | 高：需独立 brainstorm，先有底座才有纵深 |

## 4. 各子项目设计要点

### 4.1 M18 · 棋盘生长与归属可视化

- **开局空盘**：关掉演示层级通路，改走「真实地产层级」——未售 = 无楼。
- **逐级生长**：买下 → L1，升级 → L2/L3/L4/L5；**五星楼**须有肉眼可辨的体量跃迁（复用 M16 已注册的 `building.s*.l{1..5}` 与 `levelOf` 注入）。
- **归属配色**：楼体（墙体 + 屋面）走**业主色系**；并做「同业主相邻地块街廓连片同色」，使归属一眼成势力图，而非依赖楼顶名牌。
- **过渡表现**：动土 → 起楼，避免 0 直接蹦到 L5 的突兀。
- **开局保留公共设施楼（已定，只保留公共设施、商家格全空）**：现状恰相反——`TILE_LEVEL` 的 18 栋演示楼**几乎全是商家格**，而公共设施格（福利 7/27、银行 9、监狱 12、股票所 19、乐透 21、税务 23、医院 25）**全是空地砖、无楼**。推荐保留 4 栋：

  | 格 | 设施 | 推荐层级 | 理由 |
  |---|---|---|---|
  | 0 | 鹿乡特色小镇（起点） | L3 | 每回合必经，空着最掉档次 |
  | 9 | 鹿乡银行 | L2 | 高频交互 |
  | 19 | 股票交易所 | L2 | 盘面常开，需「看得见在哪」 |
  | 25 | 医院 | L2 | 停 1 回合的负反馈需要实体 |

  技术含义：公共设施格**没有可用楼型**（现有 preset 仅 `stall/shop/market3/onsenHouse/gate/barn`），M18 需新增「银行 / 医院 / 交易所」式楼型或复现有楼型 + 新招牌。

- **L1→L5 换代（现状诊断 + 推荐）**：现状 `levels >= 3` 直接切 `market3` 楼型（`src/render/providers/proc-building.ts:308-310`），L3/L4/L5 只是**行数 +1** ⇒ **L5 与 L3 几乎无差别**，这是「没有升级快感」的根因。推荐**五段式换代（每级新增构件，而非单纯长高）**：

  | 级 | 形态 | 新增构件 |
  |---|---|---|
  | L1 | 单层小摊 | 棚顶 + 幡旗（无灯、无窗格） |
  | L2 | 双层小铺 | 二层 + 雨棚 + 招牌 |
  | L3 | 三层商铺 | 三层 + 转角橱窗 + 招牌塔（现有 `prop.signTower`） |
  | L4 | 四层商厦 | 四层 + 退台（现有 `setbackBox`）+ 屋顶设备箱 + 灯笼 |
  | L5 | 地标五星 | 五层 + 塔楼尖顶 + 霓虹描边 + 业主色光晕 + 地砖发光环 |

- **待拍板（M18 设计阶段）**：业主色染**全楼体**还是只染**屋面 + 门面 + 描边**（避免整盘色块过艳、与皮肤配色体系打架）？见决策清单 D3。

### 4.2 M19 · 对抗玩法与落子沉浸

- **选目标交互**：选中道具 → 棋盘进入选目标态（可作用地块高亮呼吸）→ 点格确认 / 取消，并给**预演**（说明将发生什么、谁会受影响）。
- **拆屋的破坏力与表现**：`bombDown` 现状是「拆 1 级 + L1 炸回无主」，本期要补的是**一次夷平高级楼的销毁力**（口径待定）与**破坏的表现**（楼体崩塌 / 拆除动画，依赖 M18 让层级先可见）。破坏边界：**只作用于地产楼体，不动商家格地砖与店招**（业主授权内容）。
- **路障规则**：明确「挡自己」与「拦对手」两种用法均成立，及被撞破后的后续效果。
- **落子沉浸**：落格镜头推近 + 地块高亮脉冲 + 停顿节奏 + 分量感音效。
- **AI 同源**：AI 必须走同一套目标决策，否则道具有效性只在人类之间成立。

### 4.3 M20 · 经济闭环（拍卖 · 自由出售 · 股票交易 · 股票卡片）

**破产拍卖（口径已定：所有权转移，不从零复建）**

- 不再走 `releaseEstate` 归无主，改为**所有权转移**：成交者**直接继承该地块的所有权 + 收租权**，楼层保持原样（买到即接手现成楼）。
- 起拍价 = `sellAt()` 变卖价；可流拍，流拍处置见决策清单 D11。
- 拍卖所得**优先清偿欠款**，余额分配口径见 D13。

**自由出售房产（新增玩法）**

- 玩家可**任意回合主动变卖自有房产**以筹集资金（现状只有破产时被动自动贱卖，是「无声的剥夺感」来源之一）。
- 价格与折价口径见 D12；出售后地块回归「可购买」状态还是继续挂卖，见 D12。

**股票交易（补功能，非砍功能）**

- 现状：`buyShares/sellShares` 核心具备指定能力，但 UI 只暴露第一支且手数恒 1（见 §2 第 ⑥ 行）。
- 目标：**逐行选中标的**（点某行 = 选中该股）→ **可选数量**（口径见 D5）→ 买入 / 卖出；**支持只卖其中一支**。
- 语义修正说明：客户原话「股票不能指定买哪支，也不能选择性卖出」是**抱怨缺功能**，不是要求限制。

**股票类卡片（新增数据 + 入口）**

| 卡 | 类型 | 建议效果 | 入口 |
|---|---|---|---|
| 涨跌卡 | 道具卡（`target: stock`） | 指定一支股票，令其下回合**必涨 / 必跌** | 手牌槽 → 浮层内选股票 |
| 红利卡 | 道具卡（`target: none`） | 按持仓领分红；无持仓折现固定金额 | 手牌槽 → 点击即用 |

- 连带：`ITEM_CARDS` 由 5 种增至 7 种，手牌槽是否由 5 扩至 7 见 D9。
- 须与既有 `c-stockTip`「内幕消息」区分：内幕消息是**随机**一支，涨跌卡是**指定**一支。

**连带价值**：让「竞标」成为常规博弈入口，为 M21 的动态要约收购铺路。

### 4.4 M21 · 全新玩法候选池（每项独立可裁剪）

1. **商圈连锁**：同业主连片街区给租金 / 过路费加成，视觉上街区连成一片（把单调涨价变为布局博弈）。
2. **动态要约收购**：任何回合可对他人地块发起公开竞价，对方可拒绝但付违约金——拍卖由罕见事件变为常态心理战。
3. **街区事件**：结合多城市 / 双阳 IP（温泉季、鹿乡文旅节、台风等），盘面某街区租金与客流短时波动。
4. **信息战**：情报类道具可窥视对手手牌 / 下一张命运牌 / 市场轮盘，制造信息不对称。
5. **抵押与赎回**：替代粗暴变卖，给落后玩家翻盘空间。
6. **道具连锁反应**：路障被撞破留碎片再挡一人；悟空「筋斗云」可跳过路障——**角色技能 × 道具**组合。
7. **设施化改造**：拆屋后改建为公共设施（医院 / 学堂 / 市集），改变该格属性而非单纯清空。

## 5. 排期方案

| 方案 | 顺序 | 结论 |
|---|---|---|
| **A（已采纳）** | M18 视觉 → M19 对抗 → M20 经济 → M21 新玩法 | 每步建立在「看得见」之上，互坑与竞拍的爽感才成立；M18 同时解决最直观抱怨 |
| B | M19 对抗 → M18 → M20 → M21 | 互坑最快见效，但拆屋时看不出归属，反馈弱、返工概率高 |
| C | M20 经济 → M18 → M19 → M21 | 经济最完整，但拍卖缺归属可视化的戏剧性，且股票砍功能会先破坏现有 UI |

## 6. 交付与验收口径（每个里程碑一致）

- 单测 / 闸门：`npx tsc --noEmit`、`npm run check`（含 lint / lint:skin / vitest）、`npm run build`（含 `check-hardcoded`）。
- 取证：手机视口截图 390×844 @dpr2 入 `docs/verify/`，脚本置于 `local/mono-shots-m*.mjs`，闸门须含 `errors: []`。
- 文档：`docs/manual-mono.md` 追加对应里程碑小节并引用截图。
- 收尾：`npm run deploy` → `npm run check:prod` → commit → push（一次收口）。
- 设计呈现：每个子项目进入设计阶段时，**版式方案以内联 mockup 预览（PureShowWidget）给出 A/B/C 备选再定稿**（用户既有硬规范）。

## 7. 明确不做（YAGNI）

- 不引入联机 / 真人房间（本期仍为单机 + AI 席位）。
- 不做 3D 化或美术管线重做（沿用现有 proc 绘制与皮肤体系）。
- 不动 17 个商家格及其店招 / 地砖授权内容。
- 不为了「新玩法」而新增随机源或破坏确定性回放。
- 不在本期改动既有 v5 样张之外的场景构图（如 HUD 结构、开局流程）。
