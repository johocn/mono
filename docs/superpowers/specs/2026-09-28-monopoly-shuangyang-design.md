## §2 目标与非目标

### 2.1 目标（MVP 必须做到）

1. 手机浏览器（390×844 基准）可玩：**开局 → 掷骰 → 移动 → 踩格结算 → 买地/升级 → 收租 → 破产/胜利**。
2. 画面达到「**不低于大富翁 4 的动画水准**」——序列帧/缓动/粒子级，不是静态图堆叠（动画清单见 §5.6）。
3. 建筑有**可见的升级层级感**：L1/L2/L3 同比例对照时一眼可辨（v5 样张 C 已达成）。
4. 棋盘信息可读：32 格全部用**汉字店名标签**，标签永不被前排建筑遮挡。
5. 玩法系统闭环：买地/升级/租金、三类卡牌（道具/命运/机会）、股票交易所、监狱、福利中心、轮次与胜负判定。

### 2.2 非目标（本轮不做）

- 联机对战、房间匹配、观战、聊天（留接口，不在 MVP 范围）。
- 真实资金结算、真实股权；股票为游戏内虚拟盘。
- 美术资源（序列帧图集/龙骨）**首版不落地**：MVP 用**程序化等距绘制**（v5 已验证），后续可替换为图集。

## §3 视觉规范（v5 定稿契约）

实现阶段**直接照抄**以下几何契约，不要自由发挥；改动需回到样张同步。

### 3.1 等距投影

```
ISO = { hw: 21, hh: 10.5, ox: 195, oy: 96 }
ipos(c, r) = [ ox + (c - r) * hw, oy + (c + r) * hh ]
```

- 45° 投影：横半宽 = 2 × 纵半高，行列镜像对称。
- **深度排序**：`sort((a, b) => (a.c + a.r) - (b.c + b.r) || a.c - b.c)`（`c + r` 小者先画 = 远处先画）。

### 3.2 地砖与配色

| 元素 | 值 |
|---|---|
| 地砖 | 菱形 `dia(cx, cy, hw, hh)`，描边按类型/归属色 |
| 类型底色 | `core #5c4a1a` · `shop #2f4238` · `chance #40305c` · `fate #2b3566` · `bonus #245037` · `jail #542c25` · `stock #22465a` |
| 类型描边 | `core #f5c451` · `shop #5b7b6a` · `chance #a26bf0` · `fate #6b7ff0` · `bonus #34c759` · `jail #e5573f` · `stock #29a9e0` |
| 玩家四色 | 你 `#3fbf7f` · 老王 `#f0a039` · 丽丽 `#e0607e` · 小赵 `#4aa3e0` |
| 背景 | `#0c1513 → #1a2b2a` 纵向渐变（夜色） |
| 金色主调 | `#f5c451`（按钮/图标/店招文字） |

### 3.3 建筑三级（同比例尺）

| 层级 | 层高 `h` | 特征 |
|---|---|---|
| L1 摊位 | `26 × s` | 坡顶（四坡亭子感）、红白条纹雨篷贴左墙、暖木橱窗、无霓虹 |
| L2 门店 | `46 × s` | 两层、上层三扇暖光窗、屋顶设备箱、**右墙斜面金色店招**、门口/右侧各一盏红灯笼 |
| L3 商超楼 | `72 × s` | 三层玻璃幕墙（冷色 `rgba(176,222,246,.62)` + 内透暖光）、屋顶绿色霓虹轮廓、**屋顶招牌塔 + 天线红灯** |

**共用建构件**（三级都画，保证"真楼"质感）：

1. 橱窗 = 玻璃底 + **竖框 ×3 + 横梁 + 台度**（小面参数插值，见 `win()`）。
2. **门**：左墙中前段门洞 `#231a11` + 内透暖光 + 门槛石。
3. 楼层分隔线（L2/L3）、檐口压顶、墙脚压暗。
4. **竖招幌子**（红底金字，如「温泉」「市集」）挂于楼体左侧挑臂——L2/L3 细节量的关键一笔。

### 3.4 两条硬约束（本轮踩过的坑，实现时禁止再犯）

1. **凡"贴在墙上/屋顶上"的装饰必须减墙高**（屋顶设备箱、招牌塔、天线、雨篷/店招），否则会飘在地面或墙中间。
2. **棋盘分三遍绘制**：① 地面 + 建筑 → ② 汉字店名标签（压最上层，永不被遮挡）→ ③ 玩家棋子。店招/招牌文字必须跟随等距角度旋转（`ang = -atan2(d, w) * 180 / π ≈ -26.57°`），与墙面同一透视。

### 3.5 地块橱窗（B 版式）

- 构图：`gy = h × 0.60` 地平线 → 夜空渐变 + 月亮 + 亮窗天际线（6 行窗）→ 石板广场菱形 → 行道树 ×2 + 路灯 ×2 → 楼体居中（`s ≈ 3.2`）→ 顶部店名药丸 + 底部信息条（层级 / 路过租金 / 操作按钮）。
- 用途：踩到地块时浮起的镜头；升级弹窗复用同一构图。

## §5 玩法系统

### 5.1 回合流程

`掷骰（2 颗）→ 逐格移动动画 → 落格结算 → 可选动作（买地/升级/用卡）→ 结束回合 → 下一位`

### 5.2 买地与升级

- 无主地块：可**购买**（价格按层级阶梯，见 §5.4 占位值）。
- 自有地块：可**升级** L1→L2→L3（升级期间地块挂"施工中"状态，1 回合不可收租）。
- 他人地块：**付租金**（`RENT[层级]`），可用道具卡抵消/翻倍。

### 5.3 三类卡

| 类型 | 格数 | 说明 |
|---|---|---|
| 道具卡 | 5 种常驻手牌 | 炸弹（拆对手一级）、路障（前方设障）、免罚（免一次租金/入狱）、迁点（转向指定格）、租金翻倍 |
| 命运卡 | 6 格 | 强制事件（多为负向/中性）：罚金、传送、退格、天气停一回合等 |
| 机会卡 | 6 格 | 正向事件：奖金、免费升级、再掷一次、抽道具卡等 |

### 5.4 经济（演示数值，待平衡）

| 项 | 值 |
|---|---|
| 开局资金 | ￥3,000 |
| 经过起点 | +￥200 |
| 购买价（L1/L2/L3） | ￥60 / ￥180 / ￥420 |
| 路过租金 | `RENT = [0, 15, 45, 105]` |
| 破产线 | 现金 < 0 且无可变卖地产 |

### 5.5 特殊格

- **股票交易所**：进入后可买卖 3–5 支"双阳概念股"（虚拟盘，回合制涨跌）。
- **监狱**：进入即停 1–2 回合，可用"免罚"卡抵消。
- **福利中心**：领取随机奖励（现金/卡牌/免费升级）。

### 5.6 动画清单（"不低于大富翁 4"的验收对象）

| 场景 | 动画要求 |
|---|---|
| 掷骰 | 骰子旋转/弹跳 → 停下（≥12 帧观感，可点屏加速） |
| 移动 | 棋子逐格跳跃/带弧线，落格有回弹与落尘 |
| 买地 | 盖章/落旗动画 + 金币飞出 + 音效位 |
| 升级 | 施工脚手架 → 落成 → 灯光逐层点亮（L1→L2→L3 分层点亮是关键爽点） |
| 收租 | 金币从对手飞向持有者 + 数字滚动 |
| 卡牌 | 抽卡翻牌（3D 翻转或缩放淡入）+ 卡面高光扫过 |
| 命运/机会 | 转盘或牌堆抽取 + 屏幕轻微震动（可关） |
| 股票 | 折线实时抖动 + 涨跌红绿脉冲 |
| 破产/胜利 | 全屏特效 + 结算面板展开 |

**性能预算**：中端安卓机（骁龙 6 系）稳定 60fps；单帧绘制调用 < 200；首屏可交互 < 3s（4G）。

## §7 技术选型

### 7.1 架构分层（核心决策：逻辑与渲染解耦）

对齐仓库已落地的 `tour-game` 分层，**新工程照此复制**：

```
monopoly/
├── src/data/        # 纯 TS 常量：棋盘 32 格、卡牌、股票、店铺美术参数
├── src/core/        # 纯 TS 逻辑（零引擎）：骰子、移动、结算、升级、卡牌、股票、回合状态机
├── src/render/      # 渲染桥接层（唯一依赖引擎的目录）
├── src/ui/          # HUD/浮层（可先纯 DOM/SVG）
└── test/            # Vitest：core 全覆盖
```

**收益**：引擎选型风险被关进 `src/render/` 一个目录；`src/core/` 可单测、可跨端复用、可在无引擎环境跑回归（本项目已有 688 单测的前例，逻辑必须可测）。

### 7.2 首选：H5（PixiJS 8 + GSAP + Vite）

- 大富翁 4 是 1998 年的 2D 预渲染精灵 + 序列帧；WebGL2 的精灵/粒子/着色器**足以越过**该水准，动画上限不构成瓶颈。
- 运行时包体 gzip ≈ 300 KB（对比 LayaAir 3 ≈ 1.1 MB），首屏更轻。
- 复用现有 Web 链路：Vite 构建、`scripts/deploy.mjs` 类部署、nginx 静态目录、Playwright 移动视口截图验收（团队既有硬性流程）。
- 生态：GSAP 缓动、Spine/DragonBones 插件、Lottie（AE 导出卡牌动效）。

### 7.3 备选：LayaAir 3（决策闸门）

仓库现状：`d:\zhao\tour-game` 已是真实 LayaAir 3 工程（`tour-game.laya`），且其分层与本方案一致。**出现以下任一信号时，把 `src/render/` 换成 LayaAir 实现**（`src/core/` 与 `src/data/` 不动）：

1. 卡牌/场景动画需要**可视化时间轴编辑器**或需美术同学协作产出（龙骨/序列帧图集）；
2. 明确要做**微信小游戏 / 抖音小游戏 / 原生 App** 多端发布；
3. PixiJS 在真机上出现无法解决的性能或兼容问题。

**代价**：包体上升至 1 MB 级、需并行的 IDE 工具链（LayaAir 工程创建依赖 IDE）。

## §9 商业闭环（**待确认**）

推测意图（需用户确认后再实现）：**地块 = 真实商家广告位**，游戏是邻里商业的引流与复购工具。

- 商家**认领地块**（后台配置 / 付费），地块即该商家在游戏内的门面。
- 游戏内产出**商家券 / 积分**（复用仓库既有券与积分能力，如 `coupon-issue`、`zhao-wealth`），到店核销。
- 反向：真实消费（如商城订单）转化为游戏内资源。

以上三点**依赖仓库既有能力的具体接法尚未确认**，实现前需单独立项与确认，不与 MVP 耦合。

## §11 验收标准（硬性）

1. **手机视口截图**：每次功能测试必须用 390×844、dpr=2（780×1688）的 Playwright 移动视口截图，并补充进操作手册。
2. **单测**：`src/core` 全覆盖（骰子分布、移动越界、租金计算、升级互斥、卡牌效果、破产判定、胜负判定）。
3. **视觉回归**：M2/M3 的截图需与 v5 样张逐项对齐（棋盘疏密、建筑层级、标签遮挡）。
4. **性能**：中端安卓 60fps、首屏可交互 <3s。
5. **部署**：本地构建 → scp 上传 → 服务器仅解压/`pm2 restart`（禁止服务器构建）。
